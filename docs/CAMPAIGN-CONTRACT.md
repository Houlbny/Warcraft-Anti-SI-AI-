# Guided campaign contract

Existing project/file/run/settings/knowledge endpoints remain. Backend root owns API/lessons/tests; frontend agent owns frontend except World.tsx; world agent owns World.tsx plus optional Character.tsx only.

## New endpoints

- GET `/api/projects/{pid}/campaign`: `{status:'unprepared'|'generating'|'failed'|'ready'|'completed',role:null|'mage'|'paladin'|'druid',title:string,summary:string,quests:Quest[],current_quest_id:string|null,completed:number,total:number,error?:string,coverage?:string}`.
- POST `/api/projects/{pid}/campaign` body `{role:'mage'|'paladin'|'druid'}`. Real AI generates the selected route in saved segments, checks the whole result, publishes and returns Campaign. An explicit retry resumes compatible private draft segments. Existing published campaign of same role returns it without another call; different role returns 400 (create another practice copy). Missing model returns actionable 400; failed state retains attempted role and saved segment progress. Each unfinished segment permits one automatic corrective retry for invalid JSON or locally rejected response content (two requests maximum per segment per explicit generation attempt). HTTP/authentication/timeout, input-budget and source/config changes do not trigger automatic retries. Valid semantic consistency conflicts still require explicit continuation through the existing repair path.
- POST `/api/projects/{pid}/quests/{qid}/review` body `{answer?:string}`. For `explain`, answer required and AI evaluates source-based rubric. For `review` code tasks, requires changed source and current successful actual run before AI diff review. Returns `{correct:boolean,feedback:string,checks?:{criterion:string,passed:boolean,evidence:string}[],quest:Quest,evaluation:'ai_review'}`. Failed evaluation does not unlock.
- Existing answer endpoint for `verification_mode:'answer'` and existing run endpoint for `run` tasks. `/run` for review tasks only records result; then call `/review` to grade.

While generating, Campaign also includes `started_at` (UTC ISO time for this explicit attempt), `phase:'preparing'|'requesting'|'validating'`, `wait_timeout_seconds` and, once prepared, `source_count` and `input_bytes` (serialized current model request bytes estimated before exact configured-key masking). Failed states retain this metadata. The frontend polls GET every 3 seconds even while its POST remains pending. A browser connection failure triggers a state lookup, never an automatic duplicate POST. A ready chapter resumes; a generating chapter stays under observation; explicit failure allows manual retry. Polling ignores the previous failed attempt while the new POST has not reached the backend.

`generation` is optional for older records; current records expose `{stage:'analyzing'|'planning'|'quests'|'checking',analysis_completed:number,analysis_total:number,quests_completed:number,quests_total:number,current_quest:number|null,quest_titles:{title:string,status:'pending'|'generating'|'saved'}[],resumable:boolean,message:string}`. Quest numbering starts at 1; totals can be zero before the outline exists. A saved count does not imply a contiguous prefix: consistency repair may invalidate a middle quest and its dependants. Each public title status is authoritative. Draft answers, hints, rubric, source text and validation baselines stay private. Before publication `quests` stays empty.

Source excerpts have a 48,000-byte UTF-8 budget (6,000 per file, up to 24 files), only complete lines and up to 24 symbols inside each excerpt. These are split into bounded analysis requests. A separate planning request receives analysis and source location metadata, then each detail request receives relevant excerpts plus accepted prerequisite constraints. User JSON is limited to 24,000 UTF-8 bytes and a model request to 32,000 bytes including instructions and JSON escaping. Hashes remain local metadata. Final review receives compact summaries rather than another full chapter payload. Structural validation and role checks are deterministic; consistency assessment is AI evaluation, not actual project execution.

Private `campaign_drafts` stores each validated analysis, outline and quest detail, associated with source version, role, model URL/name and rules version. API keys and timeout preferences are not cache keys. Incompatible outlines/details are invalidated; unchanged analysis may be reused where provenance still matches. Check source and model identity around requests and before publishing. Complete chapter, quests and publication marker are committed together. An interrupted process leaves saved drafts recoverable on explicit continuation, without background auto-resume. Local `model_requests/recent` keeps the latest 20 request diagnostics (purpose, times, byte counts, timeout category/status), without prompts, source, URLs, headers or keys.

Generation metadata also includes `attempt:1|2`, `max_attempts:2`, and `validation_error:null|{field,reason,actual_type?,expected_type?,actual_length?,maximum?,message}`. The existing `message` displays corrective request progress. Analysis failures identify the batch in the user-facing error; nested field paths distinguish `summary` and `files[0].summary`. Text is trimmed before its character limit is checked; no coercion, invented default or summary truncation is used to pass validation.

Private `format_failures` keys feedback by a hash of stage, source/config identity and exact segment payload. A failed current segment's feedback is included in its one corrective request and subsequent explicit continuation; accepted segment save atomically clears that feedback. Changed source/config/outline cannot reuse obsolete feedback. `generation_diagnostics/{project_id}` retains up to 20 safe validation events (stage, batch/quest/check group, attempt, field metadata and time), without returned text, source or credentials. Diagnostic messages are bounded. Initial requests and checker grouping reserve 1,024 bytes for feedback within the existing 24k/32k budgets.

## Quest additions (existing fields remain)

`status:'locked'|'available'|'completed'`; `order:number` zero based; `verification_mode:'answer'|'explain'|'run'|'review'`; `steps:{title:string,instruction:string}[]`; `concepts:string[]`; `success_message:string`; `run_entry?:string` separate from source_file for multi-file project. AI generated step count 2–4, 6–10 quests per chapter. Hints private; request existing hint endpoint. answer/rubric are private server data. `source_file/line` always valid.

Only first incomplete quest is available; earlier completed quests reviewable. Backend rejects answering/hinting/running/reviewing locked quests. After success campaign GET and quest list reflect next available quest. Frontend shows completion panel and explicit '下一关'; do not skip silently.

## Frontend layout and flow

Full viewport stage, small functional HUD (project/role/progress; projects/library/settings buttons), current quest/dialogue and explicit action. No permanent dashboard sidebar or slogans. Import immediately opens role choice. Confirm role calls campaign POST, showing genuine busy state (no invented percent). If model incomplete, open settings with return-to-role action. On saved setting continue role generation by explicit button. No automatic model calls simply when browsing existing project. Failures allow retry and preserve choice. Existing unprepared project automatically enters this flow, even if it has legacy quests.

The waiting scene uses the selected pixel character at four stations corresponding to server stages. Saved draft nodes reflect server status, never a timer-based completion estimate. Animation can be paused and respects reduced motion; pausing decoration does not stop generation. Local manually browsable tips carry no quest answers. Failure freezes animation, retains progress and offers explicit continuation for the same role; choosing another role clearly starts a new compatible draft. Full chapter approval remains required before entering any quest.

World props: `{quests:Quest[],completed:number,onSelect:(index:number)=>void,role?:'mage'|'paladin'|'druid',currentQuestId?:string}`. Render route for dynamic count (6–10), completed/current/locked nodes, class-colored player. Locked nodes don't select. All route interactions also have accessible HTML buttons in parent. Character component optional export default `{role,size?:number}`.

SourceDiff.tsx remains reusable; Monaco workers local. Frontend updates api.ts types. Do not edit backend from frontend tasks. Do not use offline fixture tasks to silently replace AI generation. No need new packages.
