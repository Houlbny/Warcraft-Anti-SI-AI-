# 提示词编辑指南

提示词使用非空 UTF-8 Markdown，由 `backend/prompts.py` 相对应用目录加载，不依赖启动目录。本说明不会发送给模型。

| 文件 | 用途 |
| --- | --- |
| [adventures/analysis.md](adventures/analysis.md) | 识别材料类型，给出 1–3 个适配职业及理由 |
| [adventures/analysis_batch.md](adventures/analysis_batch.md) | 阅读一个原文批次，保留知识关系与真实来源 ID |
| [adventures/analysis_merge.md](adventures/analysis_merge.md) | 分组汇总批次概览，形成整体结构与职业建议 |
| [adventures/plan.md](adventures/plan.md) | 根据材料与角色规划主题、知识目标及必要前置 |
| [adventures/task.md](adventures/task.md) | 生成单任务的讲解、问题、公开标准、提示和来源引用 |
| [adventures/review_v2.md](adventures/review_v2.md) | 按公开标准评审回答，代码任务另提供改动与运行证据 |
| [connectivity/system.md](connectivity/system.md)、[user.md](connectivity/user.md) | 测试已保存接口 |

五职业方向由分析、规划与任务指令统一表达：法师侧重文档知识，圣骑士侧重脚本，德鲁伊侧重编程基础，萨满祭司侧重工程架构与实现，牧师侧重历史文化。不再使用独立旧职业提示词、固定六关或内置知识卡教材。

## 修改与生效

保存为 UTF-8（允许 BOM）。文件缺失、空白或编码错误会明确报错，没有内置旧文案回退。无需模板插值，JSON 花括号直接书写。材料、回答、实际代码与运行证据由程序提供。

分析、评审和连接测试在显式操作时读取相应文件。一次材料分析冻结分析、批次与汇总提示词；重试时提示词变化会使旧检查点失效。冒险规划时读取并保存规划与任务提示词快照，此冒险后续任务和替代任务使用保存的任务指令；因此编辑任务提示词只影响之后新规划的冒险。已发布任务不会因编辑提示词自动重写。

## 程序负责的约束

`backend/adventures.py` 校验推荐数量、职业、目标来源、必要前置无环、任务字段、公开标准与逐项评审。替代任务保留目标既定标准和执行要求。材料与模型身份变化会阻止过期发布。

所选可读材料无损分批，每批默认最多 24,000 字符及 16,000 字节 UTF-8 JSON，并依据完整请求的 32,000 字节上限自动减小。批次结果应精简且保留真实来源 ID；程序校验摘要预算，并分层归并，不能把全部摘要无限拼接。整体概览供规划使用，任务和评审重新取对应原文。每个模型请求的可重试传输与格式兼容错误共享最多两次尝试；失败保留已成功检查点，由用户显式继续。不要在提示词中承诺无限重试或绕过容量。

指令应将原文、补充解释、AI 评审和真实执行分开，不把 AI 判断写成已运行证据，也不默认玩家理解生成内容。结构校验不代表事实校验或教学质量保证。玩家自评和笔记由用户保存，不交由模型宣布目标通过；主题纪事和结语由真实完成状态确定性、幂等结算。
